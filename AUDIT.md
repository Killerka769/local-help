# AUDIT.md — Local Help

Дата аудита: 26 ноября 2026. Режим: только чтение. Сборка, миграции, БД, npm install не запускались. Визуально в браузере 360/390/768 не открывалось.

---

## 1. Резюме

Готовность к публичному запуску: **35%**.

Код умеет пройти сценарий «заявка → отклик → одобрение → контакты → закрытие → отзыв», но обещание «телефон и адрес только после одобрения» в API не выполняется. Адрес есть в ленте, в карточке заявки и в JSON чужого профиля. Телефоны отдаются в `GET /api/offers/:id` любому, у кого есть id. Регистрация — по телефону, восстановление пароля — по email, который при регистрации не спрашивают; FAQ при этом пишет, что восстановления ещё нет. `sessionVersion` проверяется только на страницах через `/api/auth/validate`; API его игнорирует, смена пароля его не увеличивает. Фильтр мата режет слова «дагестан» и «услуги» и одновременно пропускает «ЖОООППП111ААА». Пользователей нет, лента будет пустой, главный барьер опросов («не пускать незнакомца») продуктом не закрыт. Показывать ссылку людям в этом виде — сжечь первый контакт.

## 3. Маршрут API → владелец → роль → вердикт

Легенда: «владелец» = проверка, что объект принадлежит текущему userId. Middleware: публичные `startsWith` на `/api/requests|offers|reviews|feed|users|cities` (`middleware.ts:67-74,85`). Остальные `/api/*` без cookie → 401 (`:145-151`). `sessionVersion` / актуальная роль из БД на API **не** проверяются, кроме явно указанных.

## 4. Топ-5 блокеров запуска

1. **Контакты до сделки.** Адрес в ленте и в заявке. Телефоны в JSON отклика и в «моих откликах». Это ядро доверия и текст оферты. Без фикса нельзя звать живых людей.
2. **Сессии не убиваются.** Смена пароля, logout-all, бан не отзывают API-токен. Украденная cookie = 7 дней как этот человек.
3. **Восстановление пароля для реального пользователя не существует.** Телефонный аккаунт, email не обязателен, Resend в РФ, FAQ отрицает фичу.
4. **Фильтр мата ломает целевую географию и не ловит обход.** «дагестан», «услуги»; обход растяжкой+цифрами; телефон в описании не режется.
5. **Пустая лента + «не пускать незнакомца».** Технически сайт откроется. Продуктово первый визит = «ничего не найдено» и нет ответа на главный страх из улицы. Это сожжёт запуск сильнее, чем отсутствие пагинации в админке.

## 5. ЧТО НЕ НАДО ДЕЛАТЬ

- Рекламный кабинет, биллинг, «продвижение заявок», комиссии. Денег нет, платежей в РФ нет, сделок нет.
- Чат в приложении. WhatsApp/звонок и есть продукт. Чат откладывает офлайн и раздувает модерацию.

- Карты, геолокация, «помощники рядом на карте». Нет ни данных, ни лимита API.
- PWA, нативное приложение, микросервисы, Redis, Kafka, Docker, монорепо.
- Редизайн, тёмная тема, анимации, next/image на все аватары.
- 100% тестов, Storybook, отдельный дизайн-систем.
- Мультиязычность, «запуск по всей России», новые города до того, как в Махачкале есть 20 живых заявок.
- Админка «как у YouDo»: логи, роли, баны уже есть. Полировка админки при 0 пользователей — прятание от холодного старта.

- Email-рассылки «вам заявка» через Resend, пока нет домена с SPF/DKIM, который реально доставляет в Mail.ru/Yandex.

# ЧАСТЬ 2 — Честное мнение

## 1. Стоит ли год жизни?

**Условно.** Год «допиливать платформу вечерами после пиццерии» — нет. Год «проверить, берёт ли один район Махачкалы соседскую помощь через объявление, а не через код» — да, если через 8–10 недель есть цифры, а не новые фичи.

За:

1. Стек и сценарий уже собраны дальше типичного пет-проекта: заявки, отклики, бан, отзывы, юр. страницы. Год писать «ещё админку» не нужен — продукт надо выносить на улицу.
2. Опрос: ~85% теоретически согласны на соседа дешевле мастера. Боль не выдумана.
3. Ты один в городе, без зарплаты команде. Это единственное преимущество против YouDo: можно стоять в дворе с QR.

Против:

4. Частота: ~1 бытовая проблема на человека за 3 месяца (живые интервью). Приложение не станет привычкой. WhatsApp-чат дома закрывает ту же редкую задачу без регистрации.
5. Главный отказ на улице — «не пускать незнакомца». Код это не лечит. Ещё год рейтинга, жалоб и колокольчиков страх не снимет. Плюс нет модели денег: комиссий нет, рекламы не на что, 3000 ₽/мес не оплатят модерацию, если вдруг попрёт спам.

## 2. Шанс именно в Махачкале

Есть узкий шанс в формате «доска подъезда», не «YouDo Дагестана».

Что за: плотность, родственные сети, дороговизна мастеров, привычка договариваться наличными, ты локальный.

Что против: дом уже сидит в WhatsApp/Telegram; пускать чужого в квартиру в консервативной среде — хуже, чем в среднем по РФ; Авито Услуги и «мастер на час» уже есть; доверие к «сайту с рейтингом» слабое, пока нет лиц, которых узнают; телефонный аккаунт без проверки SIM = легко накрутить, если появится стимул.

Махачкала не спасёт архитектуру. Спасёт только конкретный микрорайон и офлайн-доверие.

## 3. Три сценария, 12 месяцев

Оценка грубая, не прогноз рынка. Старт: 0 пользователей, вечера 2–3 ч, бюджет ≈ 0.

| Сценарий | Вероятность | Как поймёшь |
|---|---|---|
| **Провал** | **55%** | К концу месяца 2: <30 регистраций **или** <5 заявок с уникальных людей **или** 0 офлайн-сделок. Лента пустая, ты перестаёшь постить в чаты. Признак: неделя без новой заявки не от тебя. |
| **Стагнация** | **35%** | 50–150 регистраций за год, 1–4 живые заявки в неделю, редкие сделки через знакомых. Сайт как «ещё один аккаунт». Ты поддерживаешь, потому что жалко. Признак: заявки есть, повторных авторов нет, отзывов <10. |
| **Рост** | **10%** | Один район даёт устойчивые 15–25 заявок/неделю без твоих фейков, есть повторные заказчики, сарафан («мне сосед сказал»). Признак к 4-му месяцу: ≥3 заявок/нед. не от тебя и не от друзей, хотя бы 10 завершённых с отзывом. |

10% — не «выстрелит по Дагестану». Это «живой локальный сервис», с которого всё ещё нельзя уйти с пиццерии.

## 4. Что убьёт первым

1. **Твоя усталость** — 2–3 часа после смены. Код бесконечен, улица неприятна. Легче пилить фильтр мата, чем идти в чат ЖК.
2. **Холодный старт / пустая лента** — двусторонний рынок. Исполнитель открывает пустое, не возвращается. Заказчик не видит откликов.
3. **Доверие** — барьер уже измерен. Утечка адреса (F01) его ухудшает.
4. **Продукт** (дыры сценария, два закрытия заявки, нет «что дальше») — мешает, но не первичный убийца при 0 юзерах.
5. **Конкурент** (YouDo/Авито/чаты) — чаты дома уже выиграли default. YouDo добьёт, только если ты начнёшь масштабироваться и они заметят; до этого ты просто невидим.

## 5. Главная слабость, которую код обходит

Ты строишь **закрытую платформу полного цикла** (роли, логи, экспорт ПД, SUPER_ADMIN, лимиты, мат, избранное), как будто пользователи уже есть и их надо модерировать.

Того, из-за чего человек на улице сказал «нет» — **безопасная встреча, не квартира с первого раза, понятный «свой»** — в продукте нет: ни «встреча у подъезда», ни «не публиковать точный адрес», ни онбординга «как не пускать в дом». How-it-works шаг 2: «укажите адрес».

Слабость: доводить инженерную полноту вместо распределения и доверия. Админка при нуле пользователей — это та же слабость в файлах.

## 6. Если бы я был на твоём месте

- Заморозить фичи. Починить F01–F07 и удаление аккаунта. Не больше.
- Адрес в заявке заменить на район («Тарки», «Каспийск, центр»). Точный адрес — после одобрения, в переписке/звонке.
- Написать в карточке и в оферте: «встречайтесь у подъезда / в людном месте; в квартиру — только если сами так решили».
- Один район Махачкалы, не «все города Дагестана» на главной (`app/page.tsx:99-111` — девять городов при нуле сделок).
- 4 недели: каждый день офлайн/чаты, не коммиты. Цель — 15 настоящих заявок.
- Не регистрировать друзей «для красоты ленты». Пустая честная лента + твоя заявка «помогите повесить полку, район X» лучше, чем фейк.
- Если за 8 недель нет повторных заявок от чужих людей — не pivot в «ещё фичи». Либо сузить до одного чата ЖК без сайта, либо закрыть.

## 2. Первые 100 пользователей (Махачкала)

Каналы, в порядке ожидаемой конверсии (дорогое время — не TikTok в первые 2 недели):

1. **Чаты дома/ЖК в WhatsApp и Telegram** — попросить родственников, коллег по пиццерии, соседей добавить. Пост не «стартап», а конкретная заявка.
2. **Офлайн QR** в том же доме/районе: подъезд, доска объявлений, «магнит на холодильник» не нужен — А4 в лифте, если не сорвут.
3. **Работа (пиццерия)** — смена, курьеры, постоянные клиенты: «если надо повесить / перевезти / починить, вот доска соседей, без комиссии».
4. **Универ / группы курсачей** — если есть доступ; не спамить 20 чатов одним текстом.
5. **TikTok/Reels** — только после 5–10 реальных историй («вчера сосед за 500 починил смеситель»). С нуля «скачайте приложение» в TikTok при пустой ленте — нулевой смысл.
6. Не идти сразу во все города Дагестана. Один район.

Готовые тексты:

**В чат дома (WhatsApp):**
> Соседи, сделал доску объявлений для нашего района — localhelp.ru. Если надо помочь с мелочью по дому (полка, смеситель, перенести диван) или сами можете подзаработать — заявка без комиссии, деньги напрямую. Телефон и точный адрес другому человеку открываются, только когда вы сами выберете, кто придёт. В квартиру пускать не обязательно: можно встретиться у подъезда.

**Короткий, если чат не любит длинное:**
> Доска соседской помощи по району: localhelp.ru. Без комиссии. Если интересно — напишите мне, объясню за 30 секунд.

**QR / листовка:**
> Нужна помощь по дому? Сосед сделает дешевле мастера. Local Help — localhelp.ru. Деньги наличными, напрямую. Не пускайте незнакомца в квартиру: встречайтесь у подъезда.

**На смене, устно:**
> Я сделал сайт, где соседи помогают друг другу по мелочи, без конторы и комиссии. Если у кого-то дома течёт кран или надо перенести шкаф — кину ссылку. Если умеешь что-то руками — можно откликнуться и заработать.

**Не писать:** «первый в Дагестане Uber для быта», «платформа нового поколения», «мы запустили MVP».

## 3. Холодный старт без фейков

Рабочая схема на 14 дней:

1. **Одна настоящая заявка от тебя** в своём районе, задача, которую ты и так собирался сделать (собрать мебель, вынести хлам). В тексте район, не квартира.
2. **Не создавать 10 фейковых заявок.** Пустая лента с одной живой лучше, чем мёртвые «починить iphone» от аккаунтов-клонов: первый же отклик на фейк = недоверие навсегда.
3. **Исполнителей не выдумывать.** Если отклика нет 48 часов — закрыть заявку офлайном (знакомый) и в чат дома написать результат: «сделали через соседа, вот как это выглядело». Ссылка вторична.
4. **Просить заявки, не регистрации.** «Напишите, что надо сделать, я заведу карточку» — для первых 10 людей ты можешь завести заявку вместе с ними у телефона. Регистрация ради регистрации даст 100 пустых аккаунтов.
5. **Двусторонность:** после 3–4 заказчиков лично попросить 2–3 человек с руками (курьеры, знакомые, кто чинит сам) просто открыть ленту раз в день, не сидеть в приложении.
6. **Критерий наполнения:** 10 заявок от **разных** телефонов за 14 дней. Если нет — канал не тот, не «мало фич».

## 4. Метрики

Считать руками в таблице, не строить аналитику.

**Неделя 1 (с дня, когда кинул ссылку в первый живой чат):**

- Регистрации
- Заявки (и сколько из них не твои)
- Отклики
- Одобрения
- Сообщения тебе в WhatsApp «не понял как» (это UX, не vanity)

**Месяц 1:**

- Уникальные авторы заявок
- Заявки с ≥1 откликом
- Закрытые заявки
- Отзывы
- Повторная заявка от того же человека

Явные пороги (даты ставь от дня публичной ссылки = Д0):

| Решение | Когда | Числа |
|---|---|---|
| **Продолжаю** | Д0+28 | ≥15 заявок не от тебя **и** ≥3 одобренных отклика **и** хотя бы 1 подтверждённая офлайн-сделка (отзыв или ты лично знаешь, что встретились) |
| **Pivot** | Д0+56 | Регистрации идут, заявок нет **или** заявки есть, 0 откликов. Pivot = не новые фичи, а канал: один ЖК, только WhatsApp-бот/чат без сайта, только «мастера с руками», убрать публичный адрес. Если pivot-эксперимент за 4 недели снова ноль сделок — не второй pivot в код. |
| **Закрываю** | Д0+70 | <10 чужих заявок за всё время **или** 0 сделок **и** ты пропускаешь вечера, потому что нет сил. Закрыть = поставить заглушку «сервис не развивается», удаление аккаунтов по запросу, не кормить домен вечно. |

Не считать успехом: звёзды на GitHub, лайки TikTok без заявок, 200 регистраций без второй заявки.

## 5. Первые 48 часов: регистрации есть, заявок ноль

Это ожидаемо. Регистрация ничего не стоит, заявка стоит стыда и адреса.

1. Не пилить онбординг-тултипы. Написать **каждому** из зарегистрировавшихся (телефон у тебя в админке) короткий WhatsApp: «Вижу, вы зашли. Что сейчас дома не доделано — полка, кран, переезд? Могу завести заявку за 1 минуту, адрес в ленте не светится» — **после фикса F01**. До фикса адреса так писать нельзя: ты сам светишь квартиры.
2. Свою заявку в ленту, реальную.
3. В тот же чат, откуда пришли регистрации, не «зарегистрируйтесь», а «вот живая заявка, можно откликнуться».
4. Если за 48 часов 0 заявок при >10 регистрациях — проблема не UX кнопки, а оффер. Сменить текст: не «платформа взаимопомощи», а «нужно повесить 2 полки, район X, 800 ₽».
5. Не банить, не слать email, не открывать рекламу.

# E. Минимум тестов (не coverage)

Тестов в репозитории нет. Нужны 6 ручных или простых e2e, не Jest на всё:

1. Гость: лента и карточка заявки **без** адреса и телефонов в HTML и в JSON.
2. Pending-отклик: `GET /api/offers/:id` и `GET /api/my-offers` без телефона/адреса заказчика.
3. После approve: обе стороны видят телефон; третий пользователь — нет.
4. Два параллельных approve (два клиента) — побеждает один.
5. Смена пароля / logout-all: старая cookie не проходит `POST /api/requests`.
6. Удаление аккаунта пользователя, у которого есть закрытая заявка с отзывом — 200, не 500.

Плюс по желанию: заявка со словом «услуги» и «Махачкала, Дагестан» проходит; «ЖОООППП111ААА» — нет.

# F. Инфра (кратко)

- Сборка: `package.json` `prisma generate && next build`, `vercel.json` то же. Результат build **НЕ ПРОВЕРЕН**.
- Env нужные: `DATABASE_URL`, `JWT_SECRET`, `NEXTAUTH_URL`, `RESEND_API_KEY`, `EMAIL_FROM`, `SUPER_ADMIN_PHONE`. `NEXT_PUBLIC_*` в коде не найдены.
- Cron: нет. Expired — побочный эффект ленты (F16).
- Email: Resend. Для РФ типичный провал доставки без своего домена и без Yandex/Mail.ru SMTP. Альтернатива при 0 ₽: не слать письма, поддержка в Telegram.
- Мониторинг бесплатно: Vercel logs + (по желанию) Sentry free. Не подключать, пока нет пользователей — не вместо F01.
- Откат: Vercel instant rollback. БД назад сам не откатится — нужен бэкап хостера.

# G. Юридическое (РФ)

Собрано: телефон, имя, город, адрес заявок, пароль (хеш), опционально email, IP/UA в admin log, жалобы, отзывы.

Согласие: чекбокс соглашения на клиенте, в API не пишется. Отдельного согласия на ПД нет. Политика говорит «используя платформу, вы соглашаетесь» — для 152-ФЗ слабо, плюс нет идентификации оператора.

Уведомление РКН: в коде нет и не будет; это твоя обязанность как оператора, если обрабатываешь ПД на территории РФ. **НЕ ПРОВЕРЕНО**, подавал ли ты уведомление.

Удаление: endpoint есть, может 500 (F08). Политика врёт про 30 дней и поддержку.

Оферта снимает ответственность за офлайн — это правильно для информационной доски. Она же врёт про скрытие адреса (F01). Возраст не ограничен: формально можно зарегистрировать ребёнка по телефону родителя.

Запрещённые услуги: стоп-лист переспамлен (наркотики, экстремизм, этнонимы) и дырявый. Нет отдельного списка «оружие / интим / мед. услуги / закладки». Жалобы есть, проактивной модерации нет. На старте: явный запрет в правилах + ручной просмотр первых заявок вечером. Не ИИ.
